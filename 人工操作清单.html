第 1 项：检查 player_data 集合权限⚠️ 最高

要做什么

把云数据库 player_data 集合的权限改为 「仅创建者可读写」 或 「所有用户不可读，仅管理端可写」。

在哪里做

微信开发者工具 → 云开发控制台 → 数据库 → 选中 player_data 集合 → 右上角「权限设置」

为什么必须人工做

集合权限存在云端配置里，代码仓库里完全看不到，我没有任何办法从代码确认当前是什么状态。

不做的后果

如果当前是「所有用户可读写」：

  • 任何玩家可以在小程序里直接 wx.cloud.database().collection('player_data').doc(别人的id).update(...) 改写任何人的数据
  • 本次 Phase 2 做的全部 44 项校验等于白做——攻击者根本不需要调用云函数，直接操作数据库即可
  • 排行榜可被任意改写，玩家存档可被恶意清空
怎么验证做成功了
  1. 控制台权限设置页显示「仅创建者可读写其所创建的数据」
  2. 在小程序里执行一次跨用户写入测试，应当失败：
wx.cloud.database().collection('player_data')
  .where({ _openid: '别人的openid' })
  .update({ data: { diamonds: 999999 } })
  .then(r => console.log('不该成功', r))
  .catch(e => console.log('正确被拒', e))

期望结果：报权限错误。

重要补充：收紧权限会让排行榜失效

rank.js 的排行榜是用 db.collection('player_data').orderBy(...).get() 在客户端直接读库的。

  • 收紧到「所有用户不可读」→ 排行榜读不到数据
  • 改成「仅创建者可读写」→ 同样失效（只能读到自己）

推荐做法：权限设为「所有用户不可读写」+ 排行榜改走云函数（新增 action: 'getRank'）。如果你选择收紧，告诉我，我来改这部分。

第 2 项：核实线上云函数实际部署版本高

要做什么

确认当前线上 syncPlayerData 云函数的实际代码版本，并在部署新版本前先备份旧版本。

在哪里做

云开发控制台 → 云函数 → syncPlayerData → 「版本与配置」/「代码」标签页

为什么必须人工做

NEXT_TASK.yaml 里记录了 REPORTED_DEPLOYED_BACKUP_GATE_VIOLATED——线上曾绕过备份闸门上线。加上你上传的代码与仓库任何分支都不一致，说明仓库从未保存住线上状态。云端实际跑的是什么，只有控制台能告诉你。

不做的后果
  • 如果线上云函数版本比你上传的压缩包更新，本次改动会覆盖掉某些你不知道的线上修复
  • 没有备份就部署，一旦新版本有问题，无法回滚
怎么验证做成功了
  1. 下载当前线上云函数代码，和 cloudfunctions/syncPlayerData/index.js 的基线版本（提交 e33c3129）做 diff
  2. 如果有差异，先告诉我差异内容，不要直接部署
  3. 备份文件存到本地，记录文件 SHA256 和备份时间

第 3 项：部署前在开发者工具里真机编译一次高

要做什么

用微信开发者工具打开本分支代码，确认编译通过、三个页面可正常打开、完整玩一局。

在哪里做

微信开发者工具 → 导入项目 → 选择 opt/live-baseline 分支的本地副本

为什么必须人工做

我没有微信开发者工具环境。我做的是静态检查（node --check 语法、JSON 可解析、require 路径可解析、app.json 注册文件完整性）——静态检查通过不等于 IDE 编译通过。WXSS 语法、WXML 数据绑定、基础库兼容性都要真实编译才知道。

不做的后果

可能带着编译错误上线，玩家直接白屏。

怎么验证做成功了

按这个顺序走一遍：

  1. 编译无报错、无警告
  2. 首页「投胎」能正常摇出天赋和灵根，灵根卡片下方能看到「修炼 xN.N」（本次新增）
  3. 进入游戏页，日志每 5 次闭关出一条，带进度百分比
  4. 修炼到第一次大境界突破，日志应显示 ★★★★★【飞升】
  5. 切到「仙榜」页，排行榜能加载、能切换日榜/总榜
  6. 老存档兼容性：用改动前的存档进游戏，确认不崩溃（syncFromStorage 读的字段我没动，但要实测）

第 4 项：确认激励视频广告是否开通中

要做什么

确认小程序是否已开通「激励视频广告」，如已开通则把广告位 ID 填进代码。

在哪里做
  • 开通状态：微信公众平台 → 流量主 → 广告位管理
  • 填写位置：miniprogram/services/commerce.js 第 29 行 REWARDED_VIDEO_AD_UNIT_ID: ''
为什么必须人工做

流量主开通状态和广告位 ID 在公众平台账号里，代码层面拿不到。开通还有门槛（通常要求累计独立访客达标）。

不做的后果

不填也能跑——AdService.show() 会退化为桩实现（模拟 1.5 秒后必然成功），行为和你现在线上一样，并在控制台打 console.warn。

但要注意：桩实现意味着玩家点「看广告」你没有广告收入，而奖励照发。现在发奖已经改为走服务端日限（广告换次数每日 20 次），所以不会被无限刷，但仍然是净支出。

未开通时的建议处理方式
  1. 短期：保持桩实现，但把 ad_ticket 的日限从 20 次调低（在云函数 REWARD_RULES 里改），减少白送
  2. 或者暂时隐藏「看广告得次数」入口，只保留分享得次数
  3. 中期：达到流量主开通门槛后填入广告位 ID，commerce.js 不需要改任何其他代码
怎么验证做成功了

填入广告位 ID 后，真机（不是模拟器，模拟器不支持广告）点击「看广告」应弹出真实广告；看完发奖、中途退出不发奖。

第 5 项：支付功能决策中 · 需你决策

背景：这是本次发现的收入漏损

你线上代码的 doRecharge() 对 1/6/30/98/198/648 元六个档位，一律 setTimeout 后直接发钻石——玩家不付钱就能拿到。既没有支付流程，也绕过服务端记账。

我已经改成走 PaymentService.pay()，当前返回 NOT_IMPLEMENTED 并提示「仙界商行尚未开张」。也就是说：现在这 6 个档位点了不再白送钻石，但也收不到钱。

三个选项，你选一个
选项做法适用情况
A. 暂时隐藏把 rechargeTiers 里 6 个付费档位注释掉，只留分享得钻还没做小程序支付资质
B. 接入真实支付需要：小程序已认证为企业主体 + 开通微信支付 + 新建 createOrder/paymentNotify 两个云函数想开始变现
C. 保持现状档位可见但点击提示未开张短期过渡
选 B 的话必须按这个顺序

（commerce.js 里有完整注释）

  1. 云函数 createOrder 按档位 ID 在服务端查表确定金额和钻石数（金额和钻石数绝对不能由客户端传入）
  2. 云函数调微信支付下单，返回 payment 参数
  3. 客户端 wx.requestPayment(payment)
  4. 支付结果回调打到云函数 paymentNotify

第 7 项：历史脏数据清理低

要做什么

检查 player_data 里是否已存在被刷进去的异常数据。

在哪里做

云开发控制台 → 数据库 → player_data → 按 power 字段倒序查看前几条

为什么必须人工做

我这次加的是「防止新的异常数据写入」。已经存在的脏数据需要你判断哪些是正常玩家、哪些是刷的，这个判断我做不了。

不做的后果

rank.js 的 safeBigPower() 会把超过 10³⁰ 的记录从榜单剔除（展示层防线），所以不会继续锁榜。但：

  • 脏数据仍留在数据库里占空间
  • 如果有人刷到 10²⁰ 这种「没超上界但明显不合理」的值，仍会霸榜
判断参考

正常玩家战力量级（按本次数值改动后）：

境界正常战力量级
元婴期约 10⁴ ~ 10⁵
化神期约 10⁵ ~ 10⁶
天道境圆满（通关）约 10⁸ ~ 10⁹
多次轮回叠加理论不超过 10²⁴

超过 10¹⁰ 的记录基本可以确定是刷的（除非是大量轮回的老玩家）。

怎么验证做成功了

清理后排行榜前 10 名的战力量级和境界匹配（比如「天道境」对应 10⁸~10⁹，不会出现「炼气期」挂着 10¹⁵ 战力）。
