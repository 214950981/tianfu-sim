# PLAYFEEL01 二十场关键事件：逐场施工剧本 / Controller 专用锁定稿

签发：Controller / GPT-6，2026-10-09。必须先读产品合同，再读本施工单。
适用：已在当前 Content01 里存在的原始事件，只在允许的工作分支变更；不得替换事件ID或未证明原因就改变导演/RNG抽取次数。以下“结果方向”不等于暗中加新效果，所有效果必须由实际注册 op 结算并有相符的文本。**不能实施的持续后果请改为诚实的局部体验并标明 BLOCKED，无权自行伪造。**

## 结果台词统一编辑规范
- 玩家做完选择后必须能读到：具体动作→事件发展的可见过程→结束时的实际结果（含代价或失败）。40–120汉字/结算结果，2–4句话。优先使用事件中人物、具体物件、地点、冲突，不用公式化句子“此举留下形状/冥冥中改变了命运/日后自见分晓”。
- 任一 choice outcome 都有 authored conclusion key。不存在的 resolution tier 不造“成功”。若同 choice 在结果分层下有不同效果，文案必须不同；只在奖励一致时可复用真实过程。
- “你学到了X/得到Y/与谁结盟/路线记录/道途成长”须由存档里一个真实效果支持。结果只是走了一圈，没有更深发现，也能如实写，但不可把失望做成莫名暴富。
- 当用户点击的选择有现实承诺而 Core 仅产出不相干修为：**修改合法结算或收缩选项承诺**，不能只写结果叙事遮羞。
- 结果文案可以说明具体场景中人做了什么（例如“摊主谢过你”），但不能据此宣称永久 NPC 羁绊，除非绑定的 actor 和显式效果确实落盘。
- 持续影响是否存在以新的 publicRun/publicCauses/Build及后续条件为证。结果页不暴露隐藏 NPC 属性、随机种子或未发生的 Cause echo。

## 01–07：修仙开场和四动作建立目标

### 01 初息  content01.onboarding.first-breath
原选择 keep-driving / ease-off / stop-here。产品功能：告诉新手呼吸与修为积累真实相关。
- keep-driving：继续行功，有真实修为收益；经过写气息运行与滞涩缓解或尚未平复，不能“已经凝气入境”。
- ease-off：调整方法，应有区别于强行行功的实际成本/修为；经过要说明呼吸由急转缓的得失，不强迫获得灵根新标签。
- stop-here：修得少/更谨慎且花时间；不能说获得根基突破。
- 结尾目标通过首页展示离10000/第一次突破还差多少；不能由事件文案代替修为数值。

### 02 静室  content01.onboarding.quiet-retreat
原 sit-again/change-method/close-day。做出真实取舍：进度↔时间与稳定性。
- 坐久：本次保持方法得到实际修为；换法：相应修为/时间代价；结束：少量收获或只是节省风险。
- 不能把“换个法子”写成得到永久功法，也不得因终止修炼暗加大礼包。
- 引导字段在修为满时触发“可以尝试突破”，并写出失败也会受伤的公开规则（不泄漏成功率）。

### 03 早市  content01.onboarding.market-choice
原 take-deal/haggle-fair/ask-source。摊主分药劳动，不是玩家初始有货可卖。
- take-deal：凭这次真的替摊主分类干活得到已登记的报酬；有灵石收益必须说明“报酬从摊主给出”。
- haggle-fair：先谈清价格，应真实改变收益/时间/知识，不能说成学会丹术。
- ask-source：问清来源如无线索持久化，讲明只得到口头回答或仍不清楚；不记得就是没建立追索对象。
- 明确修正“买东西但获得灵石”矛盾，不要在0灵石初始玩家身上调用无法支付的购买。

### 04 旧痕  content01.onboarding.old-trace
原 follow-fresh / mark-spot / ask-locals。当前三个只有岁月代价。
- 若暂无合法来源可写入持续线索：三个选项各有真实的短过程和不同付出的时间，结束均可说“还没有可确认的线索”，不得写成“已记录地点/以后必回此处/找到修仙遗迹”。
- 若要有后续：只用已有 Cause/已知 NPC/已有真正状态链，必须提供后续可达性证据；不得擅自加线索字段。
- 三个不同时间结果至少做“追查过什么”的差异解释；这可算20场里暂时被允许的纯时间事件之一。

### 05 山路  content01.onboarding.mountain-road
原 take-ford/scout-ridge/go-village。功能是游历的时间与情报取舍。
- 走林间近路：较省时间但方向不明；高处观察：付出观察时间，若效果只有修为必须在行为里明确“登高调息”；绕村：只有安全和时间，绝不无源发钱。
- 不能声称走村后真正认识某个NPC，除非登记。
- 理想有一个真风险路线和有代价的规避路线，借已注册风险机制并先公开预警；如果会改变冻结威胁契约，保留目前合法效果并说明。

### 06 路边伤者  content01.onboarding.roadside-injury
原 help-dress / keep-distance / just-notice。
- help-dress：若现有 generated mortal-traveler 被 materialize，NPC significance 真实增加才允许说“他记得你曾救助”；治疗不是没有修行缘由的+180修为，调整为真实情理相符的效果或描写修士以术缓伤的过程并匹配系统记录。
- keep-distance：问明情况但未记知识则只能说得知一次口头经过，不可称握有线索。
- just-notice：没有交往就不得说交了朋友；只留下真实时间/观察。
- 证明后续一次 NPC 关系公开状态或相识事件，不把创建临时 NPC 当成长期回声。

### 07 岔路  content01.onboarding.forked-path
原 clear-trail / neat-trail / hold-position，三条只有时间。
- 文案必须具体描述一个走了清楚脚印却没追到、一个追诱饵发现断路、一个审慎停留的实际结果，不能写“找到背后真相”。
- 若无 Cause，连续追索遇到只耗时间的岔路应提示“追索尚无明确对象，建议先游历寻找机缘”，让玩家有转行动作的理由。
- 这是允许纯时间的第二场，但不能连出5场类似事件。

## 08–12：日常事件要服务修仙和真实选择

### 08 旧曲  content01.ordinary.old-song
原 sit-through（修为+100）、meet-player（修为+140、时间+1）。玩家实际反馈的最大硬伤。
- 坐完：是短暂平息心绪，不是习得曲艺神通；若保留修为+100，应明示借琴音调息的可信过程，不能与修行无关。
- 起身见人：若当前没有实际持久 NPC、知识效果，就不能写“认识了谁、得知秘闻、此人会再出现”。修改为诚实的一次会面，修为要有明确的调息合理性或从真实结算中删除。
- 最终面板必须有不同的完整结局句，不许直接输出孤立修为/岁月。测试必须覆盖这个 exact event+choice。

### 09 空寻  content01.ordinary.empty-search
原 follow-footprints/redraw-map。
- 顺脚印：写明确的查探经过，有实际时间成本，失败可以是合理结果。
- 重画图：如果系统没有登记地图或知识，就只能说理清了方向但尚未形成可追踪标记，不能说“获得永久地图”。
- 不准“追踪失败却获纯修为大礼”；两选择如果合法范围仍只有时间，作为暂时纯时间第三场。

### 10 小交易  content01.ordinary.market-bargain
原 sell-herbs/trade-for-news。当前写“随身草药”，但初始物品库存不保证存在。
- 交易赚灵石必须来自当下已拥有并验证的资源、或场景即时劳动；不能凭空假定持有草药，不能用“卖随身草药”而 inventory 无草药。
- trade-for-news 声称拿到路况时：有公开真实 NPC 事实/已存线索才可称后续可追索，否则只是一次消息交流，不得假造持久地图。
- 玩家应在赚钱/得消息/欠人情之间做实质选择，扣款与资源要在数字里兑现。

### 11 山色  content01.ordinary.mountain-view
原 breathe-here/orient-and-go。
- 就地调息的修为收益合法，经过说明如何以山中灵气调息；辨方向继续上路只有行动/时间后果，不能说探索到遗迹。
- 不在追索时当作“线索确证”或与游历无关的塞池。
- 防止一连串空山色事件耗尽寿元。

### 12 半盏茶  content01.ordinary.tea-house
原 finish-cup/stay-listen。
- 喝完走：诚实短暂歇息；坐下听：是听陌生人谈旅行，如未结算NPC或线索就不能声称获得情报资源。
- 当前 stay-listen 有修为，若保留必须有可信打坐/入定过程且因果说得通，否则改为合法时间/资源效果。
- 仅日常氛围事件不得长时间挤占修仙重大机缘，Director出场权重和次数需在自动回放中检查。

## 13–16：真正产生复现的 NPC/Cause 因果

### 13 断剑客  content01.pei.broken-blade
原事件有裴照川核心NPC与 broken-sword-promise / broken-sword-rivalry 起因。
- 与人立约/以剑相争：必须依据当前合法的两条 Cause 模板分别建立关系与后果；拒绝就是不立约，不生成虚假因果。
- 不写“拜师得功法”，除非现有成就支持；必须从 fixed seed 证明后续 promise-echo、sparring-rain 等在可达条件下公开出现。
- 后续重逢台词须根据实际原因区分朋友、对手或尚未建立关系。

### 14 半张秘图  content01.xie.secret-map
原核心NPC谢听潮，两条 Cause 为 secret-map-pact / secret-map-breach。
- 立约同行应该能引出真实的后续分利/探洞机会；暗留后手需要有真实背约代价/未来警惕；拒绝不应留下已获得的整张地图。
- 没有注册 map item 时严禁宣称“秘图已入包裹”或永久追踪地图。下一幕说明具体口头约定可成立，但持续性必须和Cause记录一致。
- 每个分支都给玩家看得懂的当前目标，不再只是做选择以后放任它永远消失。

### 15 人间来信  content01.xu.mortal-letter
原NPC许长安、存在后续十年重逢/空院/旧诺。
- 回信/赴约：只用已有NPC/Cause建立真实牵绊，经过应回应树下往事而不是凭空增加修为；
- 不回：属于有代价的失去机会或时光流逝，不应仍像答应一样触发后续。
- 如果十年后确实再见，人生书可把因果串到当年选择，不许假装所有信都必兑现。

### 16 药有其价  content01.jiang.herb-price
原核心NPC姜雪芜，药费与人情。
- 认下人情/问清账目/拒绝必须是不同债务或信任状态（若相关op已存在）；资源扣除只在实际有支付能力时执行。
- 丹修/医术方面只能依据注册Build获得证据，不要靠算账就+修为而没有合理来源。
- 后续夜诊/旧账新页必须以过去真实记录的债务分支为基础。

## 17–18：道途方向会影响以后

### 17 截流一剑  content01.build.sword.river-cut
原三个通用 engage/consider/leave 模板标签。
- 出剑：必须取得现有 sword Build evidence（无效或失败也有合理代价），别把“劈开道路”变成无来源发财。
- 观察：获得不同合法修炼/准备证据或少风险；退避：真的回避损失，不可空跑路获得灵石。
- 后续一次真实Build stage/修炼修正或剑路事件条件不同，作为 G3 证据之一。

### 18 辨草  content01.build.alchemy.herb-sort
原三个 engage/consider/leave 模板标签。
- 全辨：可能有丹修Build证据；记牢两味：所得较少但风险轻；只取认识的一株：承认进度小，不虚称炼成灵丹。
- 错认药性如没有真实失败分支，不凭空写“剧毒反噬”。丹修进阶要能在公开档案看到，不是仅一次抄草名。
- 后续一次本已有的丹修场需要受到Build evidence/条件影响。

## 19–20：风险、真实死因和一次失败仍想继续

### 19 遗迹深处  content01.risk.ruin-depth
原 take-risk/read-signs/turn-away，现有注册威胁。
- 往深处：警示在点击前展示，成功/受伤/死亡分别有**不同结果短文**；不能把全部胜利写成“看见传承”，除非奖励确实登记。
- 先读征兆：是稳妥的风险策略，成功的具体价值真实、不能暗称看穿所有陷阱。
- 转身离开：没有风险暴露的对应结算，不平白领钱。
- 致命时终局要识别风险事件、公开死亡类别与年龄，不能显示“原因尚未明确”。

### 20 松林伏影  content01.risk.pine-ambush
原 take-risk/read-signs/turn-away。
- 冲出去、分辨方向、退出松林三种动作分别对应真实伤害/风险/机会，不能三选结果几乎一样。
- 失败后如不致死，给玩家后续恢复行动的合法路径；如致死，用实际 sourceEventId/category 展示死因，不凭空写某NPC杀了人。
- 所有结算结果必须和风险系统实际resolveOutcome tier完全一致，所有 tier 的叙事出现在提交以后，不提前泄漏随机结局。

## 实施后对照审计
1. 二十场逐一检查每一个 optionId / outcome tier / effect 与本施工单一致，不准将所有结果变成“经过考虑，你有所感悟”。
2. 十八局有界自动试玩主动抓取“连续5次无成长”“62岁凡人无明确突破目标”“同一场三选都是时间消耗”“死亡原因不清”“因果不兑现”。
3. 任何修复涉及 RNG 绕过、NPC actor 不可用、Cause 关联无效，宁可标 BLOCKED_CONTRACT，也不要偷偷创建第二套状态源。
4. 文案不替代机械结果；源效果改动必须记下对旧内容版本/日志的兼容性风险，本轮绝不实际部署云函数。
