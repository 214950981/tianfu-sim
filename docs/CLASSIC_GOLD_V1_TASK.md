### G02 资产权威与云函数接口（必需真正安全，不是换个位置写余额）
- [ ] 将 \`syncPlayerData\` 的通用 \`action:update\` 改为**按操作白名单分派**。个人资料仅允许指定昵称、头像等安全字段；\`diamonds\`、\`merit\`、\`ad_tickets\`、\`power\`、\`dailyPower\`、\`realm_name\`、关键角色属性、游玩进度 **不得通过通用客户端更新接口写入**。
- [ ] 身份仅由云函数 \`cloud.getWXContext().OPENID\` 获取；客户端提交的 uid/openid 不得决定被更新的玩家。文档 ID 或唯一约束确保一个 OPENID 只有一份权威档案，安全处理旧 \`_openid\` 记录、并发首次注册。
- [ ] 给「扣钻锁定摇号、扣免费票摇号、买轮回次数、功德结算、兑换属性点、锁定/加速购买、榜单膜拜奖励」各提供清晰的服务端行为接口。服务端检查余额、条件、每日限额及目标，再**一次性**扣/发，不接受客户端上传“操作后的新余额”。无可核验奖励条件时禁止发放可信资产。
- [ ] 每个涉及资产或结算的请求有唯一 \`requestId\` 与幂等处理；重复、并发、网络超时重试只结算一次。使用数据库事务/并发版本校验或等效的原子控制，拒绝负数、NaN、无穷、超大值、未知动作。更新失败保持原状态并显示可理解提示。
- [ ] \`initLifeCycle\` 功德换点改为云端一次性消费与可恢复的轮回状态（不得因 \`onShow\` / 云端回包重新执行而重复加点）。\`goToRebirth\` 重复调用只能获得一次功德；本地清档必须在可信结算及可恢复记录完成后进行。
- [ ] 清晰处理老存档：旧 \`current_run\` 和 \`global_assets\` 不可直接成为**可信充值资产或排行榜成绩**。允许本地单机恢复、迁移原版体验，云端权威资产按安全规则初始化或迁移；若无历史可信凭据，应让其仅进入非排位本地试玩，不能假装已经审计过真实性。用户已存在的可信云端记录不得被清空。
- [ ] 云函数必须对请求体结构、允许字段、事件返回码、读写错误做校验并给客户端成功/失败的确定状态；若云服务不可用，允许提示、暂停受保护操作或进入明确标记的本地试玩，**不得离线刷可信资产后联网同步**。

### G03 可信成长和榜单（不要只防钻石）
- [ ] 选用**服务端权威状态 + 有界批量推进**：服务端保存每局的关键状态和服务端时间/版本；客户端可即时显示预估进度，但无法通过上传修为/战力/境界/随机数改变云端成绩。
- [ ] 客户端向云函数请求 \`startRun\` / \`advance\` / \`breakthrough\` / \`finishRun\`（接口可按代码做少量调整）；服务器依据存档、真实经过时间、合法速度与操作条件推进，随机事件/突破结果由服务端计算。禁止把客户端提交的任意 \`elapsed\`、\`years\`、\`power\` 作为权威值；批次有服务器可验证的上限。网络重试同一批不可重复获得增长。
- [ ] 为控制微信云函数成本，采用节流/批次结算而非每帧调用；服务端应处理离线时长上限、防时间倒流、生命周期暂停、重复包、乱序回包。UI 可本地预测，但服务端返回才成为可信存档。
- [ ] 榜单改为云函数只读返回净化后的玩家公开信息和权威战力。禁客户端读取他人私有资产、存档或写排名，数据库集合访问规则必须配合；原有直查 \`player_data\` 的方式不能作为安全实现。
- [ ] 历史榜使用经验证的历史最高战力；日榜使用独立的**北京时间日期键 + 当日最高战力**，每日正确归零，改昵称不能刷新/伪造日榜成绩；采用数字字符串的正确大数比较和排序，别让 \`"99"\` 压过 \`"100"\`。不允许本地伪造对象顶替榜内名次；榜外显示“未入榜”而不是猜测准确名次。
- [ ] 若服务端权威修炼无法完整落地，必须标为阻断上线的 **P0 FAIL**，不能退回通用客户端上传 \`power\` 却宣称防作弊完成。

### G04 去除假支付和假广告发奖
- [ ] 两个页面的 \`doRecharge\` 不得在无支付凭证时增加任何钻石；购买 UI 改为“暂未开放”或禁用。保留轻量 \`PaymentService\` 接入接口，默认关闭，绝不伪造订单/实际充值。
- [ ] \`watchAd\`、\`unlockSpeedFree\` 不得仅凭 \`setTimeout\` 获得可信奖励。预留轻量 \`RewardAdService\`，未接广告时提示未开放。后续广告奖励要求后端核验可验证证据；不把可伪造的客户端回调当作付款证明。
- [ ] 分享回调 \`onShareAppMessage\` 不得直接生成可信资源；可改为明确标注的、由服务端限额发放的日常免费领取（与真实分享成功解耦），或暂时关闭奖励。
- [ ] 开发调试赠币只可在独立测试环境、明确调试开关和管理员白名单下使用，线上包必须不可调用。

### G05 存档与运行容错
- [ ] \`BigInt(runData.exp/nextExp/power/basePower)\` 前严格处理负数、空值、非法串、过长串、除零；修复异常存档无法进入页面、\`formatBigInt\` 单位越界和极大数字显示问题；云函数及返回的 JSON 不包含裸 \`BigInt\`。
- [ ] 处理 \`onShow\` / \`onHide\` / \`onUnload\` 定时器唯一性、异步旧回包覆盖新状态、\`autoRoll\` 未取消的异步回调、临界死亡/结算/重入导致重复奖励；不要无限同步/刷请求。
- [ ] 存档带 schema version 和最小兼容迁移；所有关键服务端写入应有可追踪状态版本，关闭/重启不得跳档或回档。客户端缓存是显示副本，不是财产证明。

- [ ] 检查 60 个子境界的经验门槛、预计寿命消耗、主要突破期望次数；特别检查大境界突破后 \`nextExp * 100n\`、寿命惩罚与后期指数成长，避免中后期出现绝对无法晋升的数学死局。
- [ ] 普通角色初期能够获得频繁小阶段反馈；玩家第一次死亡应有明确的功德/继承收益；连续 2~3 世能直观看到至少一项长线成长。稀有天赋有优势但不保证无脑通关。
- [ ] 五种属性和灵根不只显示文字：分别在修炼、突破、寿元、奇遇条件、资源获取等已有规则内形成可观察差异；修正概率封顶与极端数据，但不额外开发复杂天赋系统。
